# Changelog

## [0.9.0] - Preview

- Adopted the Secenter owl as the product identity: extension icon, sidebar, shared navigation rail and Dashboard hero.
- Set the Marketplace display name to `Secenter — Security Center DevSecOps`; the technical id, publisher, command ids, configuration ids and storage keys are unchanged.
- Added `media/branding/` with the authored sources and the two derivatives consumed by the manifest and the webviews, generated by `npm run branding:assets`.
- Served the brand mark through the existing `webview.asWebviewUri` mechanism, with `media/branding` added to `localResourceRoots` and the webview origin allowed in `img-src`.
- Kept scanner, provider and Companion identities distinct from the product identity, and left decorative watermarks on the neutral shield.

- Made the Security Center backend a local service the extension owns: it ships in the VSIX, starts on first use and needs neither Docker nor Python.
- Reimplemented the backend on the Node runtime VS Code provides, with the same routes, the same response shapes and the same API-key protection as the previous FastAPI service.
- Added `securityCenter.backend.mode` with Auto/Local, Remote and Docker; Docker moved from a requirement to a development and integration-testing path.
- Added a backend manager owning mode resolution, health probing, port selection, start, restart and single-flight startup, so concurrent panels start one process rather than three.
- Moved backend data to VS Code global storage, so an extension update no longer deletes scan history or the audit journal.
- Bound the local backend to 127.0.0.1 only, and gave each installation a generated API key kept in SecretStorage.
- Published the active backend address and key to `~/.security-center/backend.json`; the Burp connector reads it instead of a hard-coded 127.0.0.1:8765.
- Added the Security Center Backend card to Integrations with status, mode, resolved mode, address, version, Test connection, Restart backend and advanced configuration.
- Reported backend states as states — starting, offline, timeout, unexpected service, auth error — instead of surfacing raw connection errors.
- Prepared Security Center DevSecOps as a public preview VS Code extension.
- Added the provider-neutral Security Delivery UI path.
- Connected Security Delivery to the normalized CI/CD delivery model.
- Added provider-neutral Delivery configuration storage through `securityCenter.delivery.provider` and `securityCenter.delivery.providers`.
- Kept Jenkins as the only implemented Security Delivery provider in this preview.
- Listed GitLab CI/CD, GitHub Actions, Azure DevOps Pipelines, CircleCI and Bitbucket Pipelines as catalogue-only providers.
- Ensured Delivery secrets are stored through VS Code SecretStorage and are not rendered into webviews.
- Updated the dashboard Delivery card to read the active provider model rather than a fixed Jenkins status.
- Added Delivery integration coverage to the Integrations page.
- Preserved scanner, dashboard, runtime, infrastructure, policy, supply-chain, audit, license and dynamic security workflows.
- Documented preview status, requirements, security model, known limitations and Marketplace release blockers.
